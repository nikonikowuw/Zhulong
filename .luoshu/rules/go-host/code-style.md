# Go 代码风格规范

## 1. 换行与排版

- **断行边界**：单行超 ~120 字符按语义边界换行；多行函数签名每行一个参数。
- **4+ 参数调用**：传入 **4 个及以上参数**的函数调用，必须**每行一个参数**且右括号单独成行。

## 2. 变量声明与初始化

- **区分零值意图**：零值起始用 `var`（如 `var count int`、`var buf bytes.Buffer`），非零值用 `:=`。
- **显式初始化集合**：切片与 Map 显式初始化（`[]T{}` / `map[K]V{}`）；仅在已知明确规模时用 `make(..., 0, n)`，禁盲目大预分配。
- **结构体字面量**：必须显式指定字段名（`Type{Field: val}`），禁止按位置传字段。

## 3. 控制流清晰度

- **早返回与去 `else`**：错误与边界分支优先早返回；`if` 内以 `return` / `break` / `continue` 结尾时必须省去 `else`。
- **默认值覆盖**：简单赋值优先“先赋默认值 + 独立 `if` 或无条件 `switch` 覆盖”，替代 `else if` 链；同变量多值判断用 `switch` 并补全 `default`。
- **复杂条件拆分**：3 个及以上操作数的条件判断提取为具名布尔变量；高开销检查保留在尾部内联以利用短路求值。
- **作用域与迭代**：仅用于检查的临时变量限定在 `if init; cond` 作用域内；迭代优先 `range`（计数循环用 `for range n`）。

## 4. 函数签名与传参

- **参数上限与顺序**：函数参数 **≤4 个**（业务方法超出封装为 `Command`/`Options` 结构体，DI 构造函数超出用 `Params`/`Deps` 结构体或 `wire.Struct`）；顺序固定为 `ctx context.Context` → 输入 → 输出目标。
- **值 vs 指针传参**：`string`、基础数值、`bool`、`time.Time` 及只读小结构体（<~128B）**按值传递**；仅在修改原值、大结构体（≥128B）或 `nil` 代表业务可选语义时传指针。
- **禁止长函数裸返回**：超过 3 行的函数严禁使用 naked return。

## 5. 包组织、类型与字符串

- **文件内排序**：包注释 → imports → constants → types → 构造函数 → 方法 → helpers；关联的类型、构造与方法紧凑归组。
- **导入与导出约束**：业务包禁用点导入（`.`），空白导入（`_`）仅限 `main` 与测试包；默认不导出，最小化公开 API 表面。
- **集合与字符串**：优先使用标准库 `slices`/`maps` 及具体约束泛型（避免 `[]any` 与非必要 `reflect`）；简单数值转换用 `strconv`，循环拼串用 `strings.Builder`，错误字符串插值用 `%q` 标明边界。
