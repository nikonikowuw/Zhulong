# 算法插件架构设计

## 1. 目标与授权范围

为 Zhulong 设计可独立开发、独立编译和安装的感知算法插件架构，明确插件契约、模型资源共享、多线程执行、进程隔离及运维行为，回答“是否需要所有算法继承统一基类”，通过公共运行库减少各算法的重复实现，并支持开发期间用指定样本独立完成单次推理验包。

当前任务交付规划文档，不修改产品代码。用户已批准创建任务并确认下列产品取舍；技术设计和实施计划仍需最终审阅。设计审阅通过不自动代表授权实现、提交或归档。

## 2. 背景与仓库事实

- Go 宿主通过纯 C ABI 调用 Native 引擎。项目声明 Go `1.27.1`、C++17、固定 FFmpeg `7.1.5`；不是本任务对已安装工具链的实测结果。
- Native 已有 `HardwareFrame` 与原生资源回收机制。提交 `d4d8773` 引入 `IDecodeNode`、FFmpeg 软解与有界帧队列，`91ebc4a` 归档解码任务；本轮参考 HEAD 为 `55927a4`，未重跑其测试。
- 当前检查的 Native/Go 引擎代码没有算法插件加载器、算法工作进程或厂商推理后端；源码中未发现本地 RKNN 头文件/运行库。`HardwareFrame` 是进程内 C++ 对象，不是跨进程协议。
- 产品 PRD `docs/prd/prd-v1.0.md` §4.4–4.5 描述算法包、分析任务、跟踪与事件目标，不代表均已实现。
- `.trellis/tasks/10-05-native-ffmpeg-ingestion/prd.md:47-50` 已记录首板为 RK3568、板卡暂不在手边、镜像/SDK 未实测。本任务沿用此参考约束，不套用 RK3588 的三核策略，不推定已安装用户态为 arm64。
- 官方 RKNN 固定头文件快照含上下文复制和显式权重共享相关声明，不证明目标 Runtime 支持或实际节省内存。来源、固定 ref、SHA-256 和行号见 `research/rockchip-context-sharing.md`。
- 仓库证据与历史时效性说明见 `research/repository-baseline.md`；进程、线程和所有权分析见 `research/process-thread-model.md`。

## 3. 已确认需求

| ID | 需求与用户决定 |
| --- | --- |
| R1 独立交付 | 选择 B：算法独立编译为 `.so`，在约定平台与接口兼容范围内独立安装，不重新编译宿主。继承不是预先强制指定的实现方案。 |
| R2 信任来源 | 选择 1：首期仅接纳自己或受信任团队的插件，不开放未经审核的第三方原生代码。可信不等于无 bug。 |
| R3 感知边界 | 选择 A：插件负责前处理、一个或多个模型执行、后处理并输出结构化感知结果；通用跟踪、区域/越线规则、事件管理、存储与通知属于公共层。算法自身必需的时序状态可留在包内；公共层不等于全部放进 Go。 |
| R4 运行拓扑 | 一算法包一独立工作进程，进程内多个推理 Worker，各自独占推理上下文；目标是在兼容范围内共享模型权重资源。同包线程的原生崩溃可能影响整个包，不承诺隔离驱动/设备级故障。 |
| R5 首期平台 | Rockchip，结合已有 RK3568 参考设备记录。SDK/Runtime、驱动、模型和量化类型未确定，不将平台选择当作兼容或性能承诺。 |
| R6 共享能力真实性 | 区分主机模型文件共享、设备权重共享和每执行上下文私有内存；SDK 不支持时不能静默复制权重并宣称满足共享目标。具体收益必须实测。 |
| R7 升级 | 选择 1：仅重启对应算法包，允许该包分析短暂中断，宿主和其他包不重启。停止新任务、安全排空并释放旧进程资源后再启动新版本；不用无界缓存掩盖分析空窗。 |
| R8 崩溃恢复 | 选择 1：对仍应运行的包执行有界自动恢复，退避重试，连续失败达到上限后停止并报告。主动停用不自动拉起；设备资源状态不安全时不盲目恢复推理或复用缓冲区。 |
| R9 升级失败回滚 | 选择 1：新版本启动/就绪检查失败时，旧版本及兼容配置仍可用且资源安全，才受控尝试恢复上一可用版本。旧版本也启动失败则停止并报告，不循环切换；不把已正常运行的新版本之后的任意故障都当作自动回滚条件。 |
| R10 可维护性 | 设计须明确生命周期、数据所有权、版本兼容、错误分类、状态可观测与验证路径；不破坏现有媒体接入和 Go/Native 合同。 |
| R11 公共能力复用 | 选择 2：公共算法 `.so` 不仅提供通用图像/数学工具，还统一模型加载/查询、worker 执行上下文、私有缓冲及正常/失败路径清理，避免各插件重复实现这些操作。保留算法独立交付和进程边界；共享库代码不等于跨包共享模型或设备内存。 |
| R12 独立黑盒验包 | 开发期间读取指定的有效测试样本文件，完成一次标准推理调用，验证包符合规范、正常加载且推理入口成功完成。平台检查输出协议合法性，但不把识别内容是否正确、是否检出目标或精度达标作为验包条件；合法空结果可以通过。算法语义与精度由开发者验证，单次验包不替代既有 SDK、并发、权重共享及硬件安全测试。 |

## 4. 范围

本任务设计交付：

- SDK/插件、公共算法运行库、通用 runner、Go 进程管理、Native 帧分发和公共业务能力的责任及依赖边界，以及公共库复用对独立发布的影响。
- 独立开发与安装、跨进程数据流、进程内插件接口、模型/执行实例/任务状态与资源生命周期。
- 无需启动完整宿主的单文件、单次推理黑盒验包流程，区分接口可运行性、结果协议合规与算法精度。
- 有界调度、包级升级、崩溃恢复及受控回滚的行为和验收方式。
- Rockchip 后端的证据门槛，硬件无关验证与板端验证分阶段的实施计划。

不在本任务中顺带实现完整跟踪/规则/事件系统、前端算法管理页面或具体业务识别模型，也不将单次验包扩张为平台精度评测、批量基准或视频/RTSP 独立服务。技术设计中的目录、接口名称、参数与参考测试点是待最终审阅的建议，不是已存在 API 或已交付功能。

## 5. 明确不承诺的能力

- 本轮编写产品代码、启动实现、提交或归档。
- 新旧算法进程并存的无感升级、进程内热卸载、不可信原生代码沙箱。
- 无限重试、覆盖管理员停用意图的拉起、新旧版本反复自动切换。
- 自动修复或彻底隔离驱动/设备级故障，或在设备仍访问内存时强行回收。
- 未验证的全链路零拷贝、固定 FPS、按线程数线性扩展吞吐、固定权重节省比例。
- 将 SDK 缺失替换成伪造的 Runtime/量化信息，或把 CPU 桩通过当成 NPU 验收完成。

| AC1 | R1–R3 | 设计解释外部算法只依赖 SDK/约定运行时即可构建插件，不依赖宿主私有类；给出两个独立示例插件无需重编宿主即可安装运行的测试路径。 |
| AC2 | R1、R10 | 区分 C ABI、IPC 与内部 C++ 抽象；不强迫通过跨库 C++ 继承集成，说明 ABI 拒绝、错误返回与内存分配/释放责任。 |

## 7. 已延后但不可删除的技术验证

- 板端镜像/用户态架构、内核、Runtime/驱动/Toolkit2 版本与许可分发合同，须在目标构建与发布前补齐。
- ONNX/转换脚本、校准与量化证据、`.rknn` 身份、tensor 属性、前处理一致性，在模型相关实现前补齐；本轮模型证据门状态为 `not-applicable`（只做架构/API 研究），不等于通过模型验收。
- 上下文复制或显式权重共享、线程安全和销毁次序须按匹配 SDK 文档并实测；若不满足 R6，后端标为不支持/阻塞，另行讨论产品取舍，不自动改成多份权重。
- DMA-BUF/RGA/RKNN 的导入、格式/stride、同步和进程崩溃清理需独立闭环；先用可观测的硬件无关传输验证机制不等于放弃或完成生产优化。
