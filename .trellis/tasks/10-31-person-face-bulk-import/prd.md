# 人员人脸工业级压缩包批量导入

## Goal

支持管理员通过工业级标准 ZIP 压缩包（内含 `manifest.csv` 清单或目录自适应图片）批量导入人员档案并同步完成人脸特征建模（Face Feature Extraction），通过异步任务流水线与严格的 AI 视觉质检门禁，在确保底库数据质量的同时保障边缘宿主监控视频流的实时性与稳定性。

## Background and Confirmed Facts

- **现有人脸与人员架构**：人员领域位于 `internal/person`，人员档案包含 `name` 与可选外部工号 `personId`。
- **现有人脸录入机制**：单张人脸录入通过 `internal/person/service.go:AddFace` 完成，经由 `FaceFeatureExtractor` 接口提取 512 维特征向量后写入 `faces` 表，并通过通道热同步（Gallery Sync）广播给算法执行器（Runner）。
- **异构算力与性能约束**：与纯文本 CSV 毫秒级建档不同，人脸建模包含「图片解码 $\to$ SCRFD 人脸检测 $\to$ 关键点对齐 $\to$ ArcFace 特征提取」全链路，在边缘芯片（如 RK3568 NPU 或 CPU）上单张耗时约 100~300ms。1000 张图片处理需 2~5 分钟，**必须采用非阻塞异步任务（Async Job）+ 状态机 + 进度通知模型**，严禁使用同步 HTTP 阻塞请求。
- **实时监控防饿死（QoS）**：边缘盒子通常正运行着实时 RTSP 视频流智能分析任务，批量人脸建模的算力消耗绝对不能将 NPU/CPU 100% 占满导致视频流丢帧卡死；同时不能单张频繁跨进程 IPC 广播底库打爆管道，必须做批量热同步收敛。
- **安全与存储边界**：ZIP 文件上传涉及 Zip Slip（路径逃逸）与 Zip Bomb（解压炸弹）风险；解压产生的临时文件必须具备 RAII 级生命周期回收，严禁遗留悬空文件撑爆闪存（eMMC/SSD）。

## Requirements

### R1. 工业级数据包格式与解压规范

- **R1.1 压缩包介质**：支持标准 `.zip` 格式，文件大小上限为 200 MiB。
- **R1.2 工业清单驱动模式（首选）**：
  - ZIP 根目录下包含 `manifest.csv`（UTF-8 编码，兼容 Excel BOM）；
  - 支持字段：`name`（必填，$\le 64$ 字符）、`personId`（可选，$\le 64$ 字符）、`imagePath`（必填，相对 ZIP 根目录路径）、`isPrimary`（可选布尔值，默认 `false`）；
  - 列顺序可变，忽略多余列；字段包含空行或语法解析错误时针对该行报错。
- **R1.3 无清单自适应模式（Fallback Compatibility）**：
  - 若 ZIP 根目录无 `manifest.csv`，自动激活文件名语义解析器，扫描根目录及子目录下的图片文件；
  - 自动匹配常见命名模式：`[工号]_[姓名].ext` 或 `[姓名]_[工号].ext`；
  - 支持图片格式：JPEG（`.jpg`, `.jpeg`）、PNG（`.png`）、WebP（`.webp`）。
- **R1.4 垃圾文件过滤**：解压及扫描时，系统自动忽略 macOS 的 `__MACOSX/`、`.DS_Store` 以及 Windows 的 `Thumbs.db`、`desktop.ini` 等系统隐藏文件。
- **R1.5 纵深安全防御矩阵**：
  - **Zip Slip 路径逃逸阻断**：解压时严格使用 `filepath.Clean` 校验，解压目标绝对路径必须严格以临时任务目录为前缀，拦截任何包含 `../` 的非法路径；
  - **Zip Bomb 资源耗尽防护**：解压后总容量上限限制为 1 GiB，最大文件数限制为 1000 个；解压过程采用 `io.LimitReader` 动态计数，超限立即中止并删除已解压内容。

### R2. 异步任务生命周期与调度（QoS）

- **R2.1 异步任务创建与状态机**：
  - 客户端通过 `POST /api/v1/persons/import-face-jobs` 上传 ZIP 包，服务端完成文件初检后存入临时暂存区，立即响应 `202 Accepted` 并返回 `jobId`；
  - 任务生命周期状态：`PENDING`（排队） $\to$ `EXTRACTING`（解压与清单校验） $\to$ `PROCESSING`（AI 质检与特征提取） $\to$ `COMPLETED`（已完成） / `FAILED`（系统性失败） / `CANCELLED`（已取消）。
- **R2.2 任务可观测性与进度广播**：
  - 提供 `GET /api/v1/persons/import-face-jobs/:jobId` 轮询接口，返回总数、当前处理数、成功数、失败数、当前正在处理的文件名与耗时；
  - 支持通过既有事件流（SSE / WebSocket）实时广播导入进度事件。
- **R2.3 QoS 算力防饿死调度**：
  - 后台 Worker 采用受控并发（RK3568 等低功耗边缘端限制为 1 个并发 Worker，x86 端可配置最多 2 个）；
  - 每完成单张图片的特征提取后，主动执行微秒级调度让渡（Yield），确保宿主实时视频分析任务的 NPU/CPU 资源配额不受挤压。
- **R2.4 底库同步风暴抑制（Gallery Sync Batching）**：
  - 批量导入处理期间，挂起单张人脸即时 IPC 广播；
  - 在整批处理完毕后（或每满 50 张人脸批次），触发一次聚合底库增量热同步，降低进程间通信开销。

### R3. AI 视觉准入门禁（工业底库质检）

工业级人脸底库绝不录入模糊、遮挡或有歧义的照片，每张图片必须通过严格的四道 AI 质检门禁：

- **R3.1 格式与像素防爆门禁**：
  - 使用图像头探测（`image.DecodeConfig`）校验宽高尺寸；
  - 任意单边超过 4096 像素、图片损坏或解码失败的图片直接拒绝，错误码：`CORRUPT_OR_OVERSIZED_IMAGE`。
- **R3.2 人脸检出计数门禁（严格防御）**：
  - **零人脸检出**：置信度 $\ge 0.5$ 且检出人脸数为 0 时，拒绝入库，错误码：`NO_FACE_DETECTED`；
  - **多人合影照**：检出人脸数 $\ge 2$ 时，**硬性拒绝入库**（严禁系统盲目猜测目标人脸，须由人工复核），错误码：`MULTIPLE_FACES_DETECTED`。
- **R3.3 人脸尺寸与姿态门禁**：
  - 人脸外接框边界短边 $< 80\text{ px}$ 判定为像素过低，拒绝入库，错误码：`FACE_TOO_SMALL`；
  - 偏航角（Yaw）或俯仰角（Pitch）超出安全范围（如 $> 35^\circ$ 大侧脸/大仰头）时拒绝入库，错误码：`FACE_POSE_EXCEED`。
- **R3.4 特征建模**：通过全部门禁的照片提取 512 维 float32 特征向量并持久化。

### R4. 业务合并与冲突策略

- **R4.1 新人员自动建档**：
  - 若照片关联的 `personId` 在数据库中不存在，自动新建人员档案（`name`, `personId`）；
  - 首次入库的合规人脸自动设为主人脸（`is_primary = true`）。
- **R4.2 存量人员一人多照追加（`APPEND` 模式，工业标准默认）**：
  - 若 `personId` 已存在且姓名一致，自动将新人脸追加至该人员底库（每人上限 10 张底库照片）；
  - 若该人员此前未指定主人脸，或清单显式声明 `isPrimary=true`，则更新为主底库。
- **R4.3 身份冲突防御**：
  - 若 `personId` 已存在但导入清单中的 `name` 与库中不一致，标记该行为 `PERSON_NAME_MISMATCH` 并跳过，防止跨人员串录底库。

### R5. 失败诊断报告与存储 RAII 回收

- **R5.1 失败明细导出**：
  - 任务完成后提供 `GET /api/v1/persons/import-face-jobs/:jobId/failed-report`；
  - 导出 CSV 报告，包含：原始行号/文件路径、姓名、工号、确切失败错误代码及本地化中文/英文说明。
- **R5.2 存储资源 RAII 闭环**：
  - 每个任务独占 `data/tmp/import_<jobId>` 隔离目录；
  - 无论任务正常完成、异常中止、用户取消还是服务异常重启，临时目录均在任务终止后彻底删除；宿主启动时自动执行孤儿临时目录扫描清理。

### R6. 前端用户体验 (UX)

- **R6.1 批量导入入口与上传交互**：
  - 人员页面增加「人脸批量导入」入口；
  - 弹窗支持拖拽上传 ZIP 包，展示大小限制与标准打包规范说明，提供标准模板包示例下载。
- **R6.2 异步任务进度看板**：
  - 上传完成后进入任务看板，显示实时环形/条形进度、已处理/总数、成功/失败数、耗时预估及当前处理文件；
  - 支持关闭弹窗后台执行，全局导航栏或人员页保留任务徽标状态，点击可重新打开看板。
- **R6.3 结果汇总与失败导出**：
  - 任务完成显示结果总结卡片；
  - 存在失败项时，高亮显示失败列表并提供「下载失败报告 CSV」按钮。
- **R6.4 多语言支持**：全部前端界面与错误提示完整支持简体中文、繁体中文和英文。

## Acceptance Criteria

- **AC1（ZIP 规范解析）**：上传含 `manifest.csv` 的标准 ZIP 包能正确解压并解析各行字段，立即返回 HTTP `202 Accepted` 与 `jobId`。
- **AC2（自适应文件名模式）**：无清单的 ZIP 包能够正确通过正则识别 `工号_姓名.jpg` 并完成建人与录脸。
- **AC3（安全防御）**：包含 `../` 路径穿越或超过 1 GiB 解压总量的恶意 ZIP 包被安全拦截阻断，返回确切安全错误，临时文件立即抹除。
- **AC4（AI 门禁防御）**：零人脸图片（风景照）准确识别为 `NO_FACE_DETECTED`；多人合照准确识别为 `MULTIPLE_FACES_DETECTED` 并不予录入；低分辨率/大偏角人脸准确拦截。
- **AC5（存量人员合并）**：对库中已存在的工号执行 `APPEND` 一人多照追加，正确绑定人员 ID 并入库 `faces` 表；姓名不匹配时按冲突拒绝。
- **AC6（QoS 与底库同步）**：后台低优先级 Worker 串行/受控运行，导入期间不影响正在进行的实时视频流分析；任务结束触发一次聚合底库增量同步。
- **AC7（临时目录回收）**：任务结束或取消后，`data/tmp/` 下的任务临时目录被 100% 清理，服务重启具备残留清理能力。
- **AC8（前端交互闭环）**：前端支持 ZIP 上传、进度条实时刷新、后台最小化运行、结果展示与失败报告下载，覆盖简/繁/英三语。
- **AC9（质量与文档门禁）**：API 契约包含 Swagger 文档，单元测试与前端组件测试覆盖核心路径，`make go-check` 与 `make frontend-check` 正常通过。

## Out of Scope

- 导入视频切片并自动抽取人脸关键帧（仅支持静态图片）。
- 云端第三方人脸识别服务同步（保持纯本地优先）。
- 分布式多节点任务调度（Zhulong 为单机边缘宿主架构）。

## Key Decisions

- **异步任务模式**：因 NPU/CPU 特征提取计算耗时长，采用 `202 Accepted` + 后台 Worker + 状态轮询/SSE 广播，彻底与同步 HTTP 解耦。
- **合影照片拒绝策略**：工业标准严禁对多人合照盲目选脸，统一以 `MULTIPLE_FACES_DETECTED` 拦截并交由人工处理。
- **存量工号默认策略**：默认采用 `APPEND`（一人多照，丰富底库特征），且严格校验姓名一致性。
- **底库同步风暴抑制**：整批完成后聚合一次性 IPC 广播，避免高频 IPC 击穿管道。

## Risks and Deferred Items

- **边缘端热压力**：在 RK3568 等无风扇被动散热盒子上连续推理 1000 张人脸可能导致芯片升温降频，因此 Worker 必须引入微秒级调度让渡与温控容忍。
- **存储配额**：解压上限严格控制在 1 GiB，防止把小容量 eMMC（如 16GB/32GB 版）写满导致系统崩溃。
