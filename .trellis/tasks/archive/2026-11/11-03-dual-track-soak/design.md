# 设计摘要：双轨联调（D · 门禁与实测）

> 完整验收定义见父任务 `design.md` §6.3 / §8。本任务不改产品行为。

## 门禁设计

| 门禁 | 内容 | 判据 |
| :--- | :--- | :--- |
| 静态 | `make check` | 全绿即通过 |
| 交叉 | `make cross-board` | 产物在 `build/targets/<name>/`，仅编译不执行测试 |
| 内嵌 SPA | `webui-dist-check` | `web/dist` 与 `internal/webui/dist` 内容不一致即失败并提示 `make frontend-build`；`web/dist` 不存在只告警 |
| 不收听回归 | 整页默认静音 | 预览 WS 二进制帧与改造前逐字节一致，无音频连接建立 |
| 多客户端 | 两个登录会话 | 各自一条音频通道，互不干扰；同会话第二条接管旧的 |

## 同步测量（AC-3 的可证伪定义）

1. 合成源：画面每 2s 白闪 + 同时 1kHz/100ms beep；
2. 240fps 录屏（或采集卡同时录屏幕与音频）；
3. 逐帧对齐闪光帧与 beep 起始帧，统计 |Δ|；
4. 判定：稳态中位数 ≤ 80ms；一次视频重同步后 500ms 内回到 ≤ 80ms；10 分钟内首尾各 1 分钟均值差 ≤ 20ms。

## 板端压测记录字段

- CPU（总/单进程，含 `perf top` 采样）、RSS 曲线、订阅断链次数、`audioDroppedPreKey` / `audioDroppedBackpressure`、`GOPTruncations`、`LagResyncs` / `QueueResyncs`；
- 对照组：完全不收听（前端不解禁、不建立音频通道）；
- 结论必须写“有量化差异 / 无差异”，不写“感觉差不多”。

## 回滚演练

`audio=false` 这个开关已经不存在。演练改为：前端静音/卸载 → 音频通道关闭且 native 订阅排空；回退前端 → 音频入口消失、预览不受影响；同会话开两个 tab → 后开的接管前面的。

## 风险

| 风险 | 处理 |
| :--- | :--- |
| 板端音频 SETUP 在真实相机上失败 | 依赖 A 的自动降级；现场日志作为证据 |
| 30 分钟压测发现 RSS 增长 | 先定位是否音频环/控制帧泄漏，再回到 B/C 修 |
| 同步测量受录屏设备本身偏差影响 | 同一设备录基线与改造后，比较**差值**而非绝对值 |
