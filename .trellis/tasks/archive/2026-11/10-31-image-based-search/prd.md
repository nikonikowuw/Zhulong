# 以图搜图（人员底库 1:N 检索与业务联动）— PRD

## 1. 目标与价值

为 Zhulong 边缘智能运维宿主提供一级导航的**以图搜图工作台**。用户上传一张人脸照片，系统在已登记的人脸底库中返回按相似度排序的候选人员，并可跳转查看其历史识别记录、时空轨迹和人员档案。

本功能提供候选检索，不构成身份确认，不自动触发告警、处置或业务决策；候选结果必须由用户核验。

## 2. 工程事实与约束

1. **特征提取**：Go 宿主通过 `faceextract` IPC 请求当前 `face_recognition` 算法包提取单个 512 维 Float32 L2 归一化向量。图片检出多张脸时，当前算法选择检测分数最高的一张；Go/IPC 响应不返回人脸框或检测数量。本期 UI 展示未标注的原图预览，并提示使用仅含一张清晰人脸的照片。
2. **底库向量**：`person_faces.feature_vector` 保存 512 个 Float32（2048 字节）。向量维度和归一化本身不能证明不同模型版本的向量空间兼容。上线前必须确认现存底库向量与查询提取器来自兼容的模型构建；若无法确认，停止上线并另行定义版本标记与底库重算方案。模型升级后，必须先确认兼容性；不兼容时应在重新提取底库向量完成前禁用本功能。
3. **抓拍记录**：`recognitions` 保存实时识别记录和匹配人员信息，但不保存陌生抓拍帧的原始特征向量。因此本期不支持对未登记陌生人的历史抓拍做离线以图搜图。
4. **轨迹服务**：后端已有按人员 ID 查询跨摄像头轨迹的能力；当前 `/spatial` 前端不读取 `personId` URL 参数，也不会自动发起查询。本期需补齐该页面的 URL 状态与自动查询行为。
5. **图像输入**：支持静态 JPEG、PNG、WebP；单文件上限 10 MiB，解码图像单边不得超过 4096 像素。动图 WebP 不支持。

## 3. 功能需求

### 3.1 后端服务（`internal/person`）

- **REQ-B1 接口**：在 `UploadRoutes` 注册 `POST /api/v1/persons/search-by-image`，请求为 `multipart/form-data`。
- 必填字段 `image`；可选 `threshold`（Float，默认 `0.70`，范围 `[0,1]`）；可选 `topK`（整数，默认 `10`，范围 `[1,50]`）。
- 响应遵循 `httputil` 信封，载荷为 `ImageSearchResponse{ matches: []ImageSearchMatchInfo }`。每个匹配包含：内部人员行 ID `personId`、可空外部业务 ID `personExternalId`、`personName`、实际命中的 `matchedFaceId`、原始余弦 `similarity`。不得在响应中暴露服务器文件系统路径。
- **REQ-B2 输入与错误**：对文件 part 单独限制 10 MiB；不得只依赖 UploadRoutes 的全局请求体上限。错误映射如下：

  | 条件 | HTTP | code |
  | --- | --- | --- |
  | 缺少文件、参数格式错误或超出阈值/Top-K 范围 | 422 | `VALIDATION_FAILED` |
  | 图片文件超过 10 MiB | 413 | `FILE_TOO_LARGE` |
  | 图片损坏或格式不支持 | 400 | `UNSUPPORTED_IMAGE_FORMAT` |
  | 未检测到可用人脸 | 400 | `NO_FACE_DETECTED` |
  | 提取器不可用、超时或内部失败 | 500 | `EXTRACTOR_ERROR` |
- **REQ-B3 检索与排序**：查询有效底库向量，校验维度为 512 且数值有限；计算归一化向量点积并将数值误差限制在 `[-1,1]`。按内部 `person_id` 聚合，每人只返回其最高相似度对应的面容；应用阈值、降序排序并截断至 `topK`。相似度为余弦分数，不是概率。
- **REQ-B4 数据处理**：查询图片只在本次请求处理期间驻留内存，不写入磁盘、数据库或持久化缓存；应用日志和审计记录不得包含原图、特征向量或文件内容。记录搜索操作的操作者、时间、结果状态和结果数量，不记录完整候选列表。接口必须受现有认证保护。

### 3.2 前端工作台（`web/src/features/image-search`）

- **REQ-F1 导航与路由**：在侧边栏 `General` 组、Records / E-Map 附近新增 `Visual Search` 一级导航，使用 `ScanFace` 图标；路由为 `/_authenticated/image-search/`。
- **REQ-F2 上传与检索**：支持拖放或选择静态 JPEG/PNG/WebP、本地预览、清除重置；提示优先使用仅含一张清晰人脸的照片。多脸图片按工程现状使用检测分数最高的人脸，页面不绘制人脸框。阈值默认 70%、步长 5%；Top-K 选项为 10 / 20 / 50。显示上传进度、检索加载态，并在提交中禁用重复操作。
- **REQ-F3 结果呈现**：无搜索、无命中、错误和加载态均有明确状态。每张结果卡展示姓名、外部业务 ID（若有）、相似度百分比和底库中**实际命中的面容照片**。分数标注为“相似度”，不得显示为“置信度”或用固定 80% 色阶暗示身份已确认。原图预览不加框；界面明确提示结果需人工核验。
- 底库图像通过已有受保护的人员面容图片端点访问，URL 由内部人员 ID 与 `matchedFaceId` 构造；不直接使用响应中的磁盘路径。
- **REQ-F4 业务联动**：
  - 抓拍记录：跳转 `/records?personId=<内部人员行ID>`，页面按该 ID 查询识别记录。
  - 时空轨迹：跳转 `/spatial?targetType=person&personId=<内部人员行ID>`。空间页选用当前/默认地图、时间范围默认“今天”，地图与人员数据就绪后自动查询；若无已配置地图，则保留人员条件并提示需先配置地图，不发送查询。
  - 人员档案：跳转 `/persons?personId=<内部人员行ID>`，按精确 ID 获取该人员并打开现有人员/面容档案对话框；关闭档案时清除该 URL 参数。不得以姓名模糊搜索代替精确定位。
- **REQ-F5 国际化**：完整支持项目已有的 `en`、`zh-Hans`、`zh-Hant` 三种语言，并在 i18n 资源中注册 `imageSearch` 命名空间。

## 4. 非本期范围

- 未登记陌生人的历史抓拍离线检索；车辆以图搜图或行人全身 ReID。
- 百万级外置向量数据库。本期按不超过 10,000 张底库面容模板作为本地精确检索的初始容量目标；超过该规模的索引方案另行评估。
- 返回查询图人脸框或支持用户在多张脸之间选择。本期遵循提取器“取检测分数最高人脸”的现有行为。

## 5. 验收标准

- **AC-1 检索与排序**：用固定向量夹具验证点积、同人多面容取最大值、降序、Top-K 和阈值边界；用当前正式算法包的登记照片做集成验证，确认实际命中 `matchedFaceId` 与预期一致。不得将单个样本外推为普遍识别准确率。
- **AC-2 图像输入**：无脸、损坏/不支持格式、超 10 MiB、超尺寸图片分别返回约定信封与状态码，不产生 Panic；多脸输入遵循当前最高检测分数人脸策略，UI 不绘制误导性框。
- **AC-3 参数边界**：验证缺少文件、非法浮点/整数、`threshold` 越界、`topK` 越界及默认参数；阈值过滤对边界分数行为确定。
- **AC-4 联动**：抓拍页实际按内部 `personId` 查询；E-Map 自动以人员目标和默认时间范围执行查询，且使用默认地图；档案页精确定位并打开目标人员档案。分别验证无地图和无历史记录的空状态。
- **AC-5 数据处理**：审计记录不含图片字节、特征向量和候选明细；查询图片不会写入磁盘或数据库；浏览器预览资源在清除、替换和卸载时释放。
- **AC-6 模型兼容门禁**：发布前记录当前算法包/模型构建身份，并确认已有底库向量与查询向量兼容。不能确认时不得启用搜索，需先完成版本追踪或底库重算设计。
- **AC-7 质量与性能证据**：后端向量逻辑和 Handler 测试通过 `go test -race`；前端 API 与工作台测试、`pnpm build` 通过。性能报告记录目标设备与版本、1k/5k/10k 面容模板下的向量读取、纯排序和完整请求耗时（P50/P95）及峰值内存；未有实测前不承诺端到端 5ms。
