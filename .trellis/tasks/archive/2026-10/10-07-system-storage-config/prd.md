# 边缘异构系统媒体存储配置与动态生命周期管理 (Media Storage Configuration & Lifecycle Management)

## Goal

为面向极端边缘异构 Linux 设备（如 RK3588、NVIDIA Jetson、华为昇腾及通用工控机）的烛龙（Zhulong）单应用服务，提供工业级应用媒体存储配置管理与文件生命周期保护。
覆盖媒体存储根路径安全绑定、实时挂载容量与健康指标采集、外挂盘掉线防穿透写入保护、热切换新路径与旧数据平滑淘汰、双水位滞后回差清理引擎、极限低空间熔断停录保护，以及 Web 端容量大盘与渐进式策略配置。

## Scope

本次任务采用**全链路端到端交付（前后端 + 存储引擎 + WebUI）**：
1. **Go 后端媒体存储引擎 (`internal/storage`)**：
   - 存储根路径合法性预检（路径存在性、读写权能探测、文件系统只读检测、外挂挂载点设备号 `st_dev` 绑定与掉线防穿透）。
   - 实时存储遥测探针（基于 Linux `statfs` 采集挂载点总容量、已用空间、空闲空间、Zhulong 媒体目录细分占用，标记存储健康状态）。
   - 业务分类生命周期策略模型（录像 `recordings`、AI 告警抓拍 `snapshots`、临时导出 `exports` 独立天数/TTL 与软共享配额）。
   - 双水位滞后回差清理调度器（高水位 90% 激活、低水位 80% 停止休眠，避免磁盘 I/O 频繁颠簸）。
   - 批次步进 I/O 避让机制（分批次删除与毫秒级休眠让渡，杜绝 ext4/jbd2 元数据锁死导致视频录制掉帧）。
   - 极限容量熔断断尾保护（剩余空间 < 2GB 或使用率 > 95% 时触发主动停录与 Critical 告警，保全 SQLite 与系统安全）。
   - 路径热切换与存量数据平滑消亡（新数据写新路径，旧数据只读回放，禁止大文件跨盘搬迁，FIFO 优先清理旧盘）。
   - RESTful API 挂载与 Swagger 2.0 文档注解，集成至 Uber Fx 依赖注入生命周期。
2. **React 前端交互 (`web/src/features/systemSettings` / `features/storage`)**：
   - 全局信息架构集成：在「系统设置」（`#settings`）二级导航中展示「存储设置」。
   - 可视化容量与健康大盘：多色分段进度条直观呈现总容量、录像占用、抓拍占用、导出占用、系统占用与剩余空间，卡片式展示状态徽标（Normal / Warning / Cleaning / Emergency Stopped）。
   - 核心与高级渐进式配置表单：核心区暴露存储根路径（配备一键「路径检测」按钮）与保留天数；高级折叠面板（Accordion）提供高低水位线与紧急熔断阈值微调，以及「立即清理」手动触发入口。
   - 全文国际化（英文 `en`、简体中文 `zh-Hans`、繁体中文 `zh-Hant`）。

## Target Scenarios

1. **现场外挂大容量 SSD 初始化与绑定**：工程人员现场为工控机插入一块 NVMe SSD 并挂载到 `/mnt/storage`，在 Web 存储设置中填入该路径并点击「检测路径」，系统立即校验读写权限和设备独立性，保存后新录像无缝切入新盘。
2. **多路视频高并发写入下的平稳水位控制**：多路 4K 摄像头全天持续写入，当磁盘使用率攀升至 90% 时，后台清理协程自动唤醒，以每次 30 个文件的节奏平稳步进清理最早的过期录像，直到磁盘降至 80% 低水位以下休眠，录像流全程 0 掉帧、0 花屏。
3. **外挂存储掉盘防穿透灾难**：外挂 SATA 机械硬盘因供电不稳或硬件故障脱机，`/mnt/storage` 退化为 eMMC 根文件系统。系统预检协程敏锐捕捉到设备号突变，立即触发穿透防御熔断，拒绝向该目录写入，阻止根分区被录像填满变砖。
4. **突发外部写满与极限熔断自愈**：第三方程序意外填满磁盘或写入速度远超清理速度，磁盘剩余空间骤降至 2GB 以下。存储引擎主动暂停新录像写入，发出 Critical 告警通知，保护 SQLite 数据库和系统核心服务免于 `ENOSPC` 崩溃；运维清理磁盘或水位回升后，录像自动恢复。
5. **换盘平滑过渡与旧数据自然淘汰**：更换新存储路径后，历史视频依然能在回放界面流畅点播，清理协程在淘汰时优先清理旧路径上的历史切片，最终旧盘完全腾空，全程无数 TB 级文件后台拷贝的 I/O 灾难。

## Requirements

### 1. 媒体存储根路径管理与防穿透安全保护
- **规范化目录组织**：媒体根路径下自动维护标准子目录：
  - `recordings/{camera_id}/{YYYY-MM-DD}/{HH-MM-SS}.mp4`（视频录像流）
  - `snapshots/{camera_id}/{YYYY-MM-DD}/{event_id}.jpg`（AI 抓拍告警图）
  - `exports/{task_id}.mp4`（临时导出切片）
- **路径预检与测试接口 (`POST /api/v1/system/storage/test`)**：
  - 测试指定路径的存在性与创建权（`os.MkdirAll`）；
  - 测试真实读写与删除权限（写入临时隐藏文件 `.` 前缀并验证后清理）；
  - 验证文件系统状态（非只读挂载 `MS_RDONLY`）；
  - 获取该路径所在文件系统的独立设备标识（`st_dev` / 挂载点源）。
- **外挂存储防穿透 (Fallthrough Protection)**：
  - 当配置的路径属于独立挂载点时，系统固化记录其基准设备 ID。运行时若检测到路径设备 ID 突变退化为系统根分区 `/`（即掉盘退化为普通空目录），立即触发防穿透安全锁，拒绝落盘写入并上报故障。
- **热切换与无搬迁平滑过渡**：
  - 允许在 Web 修改媒体根路径，配置更新后新视频切片立刻写入新目录；
  - 历史切片索引记录原有物理路径，回放保持只读可用；
  - 清理引擎优先清理旧路径上的存量数据，直至完全排空，禁止全量后台同步复制。

### 2. 存储卷容量指标采集与状态看板
- **内核级存储遥测**：
  - 基于 Linux `statfs` 系统调用（通过 `golang.org/x/sys/unix` 或 `syscall.Statfs`），毫秒级获取块大小、总空间、已用空间、空闲空间；
  - 周期性/增量统计 Zhulong 自身文件占用（录像占用、抓拍占用、导出占用），避免频繁递归扫描整个大盘导致 I/O 拥塞。
- **运行状态分类**：
  - `healthy`：使用率低于高水位线，读写正常；
  - `warning`：使用率触及高水位（如 >90%）或剩余空间偏低；
  - `cleaning`：清理协程正在步进释放空间；
  - `emergency_stopped`：触碰极限硬红线（>95% 或剩余 <2GB），写入暂停熔断；
  - `error`：路径丢失、只读错误或外挂盘掉线。

### 3. 业务分类生命周期与优先级策略
- **规则配置项**：
  - `recordings_retention_days`：录像保留天数（默认 15 天，范围 1~365 天）；
  - `snapshots_retention_days`：AI 抓拍保留天数（默认 90 天，范围 1~730 天）；
  - `exports_retention_hours`：临时导出文件生存期 TTL（默认 48 小时，范围 1~168 小时）；
  - `high_watermark_percent`：高水位清理阈值（默认 90%，范围 50%~95%）；
  - `low_watermark_percent`：低水位休眠阈值（默认 80%，范围 40%~85%，且必须小于高水位）；
  - `emergency_stop_percent`：紧急停录红线（默认 95%，范围 90%~99%）；
  - `emergency_stop_min_mb`：紧急停录最小空闲空间（默认 2048 MB）。
- **软共享与优先级级联淘汰 (FIFO Cascade)**：
  - 各类文件软共享总物理空间，优先遵循自然留存天数；
  - 触碰高水位时，执行三级阶梯淘汰：
    1. 第一级：强制清理已超期的临时导出文件（`exports`）；
    2. 第二级：按生成时间由远及近 FIFO 清理普通未加锁录像切片（`recordings`）；
    3. 第三级保护：严格保全带有 AI 告警事件标记或用户收藏加锁的录像与抓拍，直到普通录像清理完毕仍空间不足时才告警，严禁误杀高价值证据。

### 4. 批次步进流控与后台调度器
- **调度周期**：
  - 常规巡检定时器：每 10 分钟检测一次 `statfs` 水位；
  - 写入事件感知：视频段写入完成时若处于预警区间可轻量通知；
  - 到期清理日程：每日定时执行常规超期扫描。
- **I/O 避让调度器 (Throttled Cleaner)**：
  - 清理操作以批次（Batch，如每批 20 个文件）为单元；
  - 批次之间执行主动让渡（如 `time.Sleep(50ms)`），释放 ext4 日志与磁盘队列锁，确保前台录像线程 0 卡顿；
  - 清理过程支持 Context 取消与优雅退出。

### 5. 极限容量硬红线与系统熔断
- **熔断机制**：
  - 运行时写入前检查剩余空间，若使用率 ≥ `emergency_stop_percent` 或可用空间 < `emergency_stop_min_mb`，立即激活熔断；
  - 存储引擎向视频录制模块暴露 `CanWrite() bool` 判决能力；
  - 熔断时上报系统级 Critical 告警通知，停止创建新视频文件；
  - 当清理协程或外部释放使空间恢复至安全水位后，自动解除熔断并恢复录像。

### 6. 前端界面交互与信息架构
- **页面入口**：`web/src/features/systemSettings`，侧边栏二级导航接入「存储设置」。
- **看板展示**：
  - 顶部容量进度条卡片（支持清晰色彩分区：录像/抓拍/导出/系统/可用）；
  - 挂载点与磁盘状态徽章；
- **配置表单**：
  - 核心输入区：媒体存储根路径、路径测试按钮、录像保留天数、抓拍保留天数；
  - 高级折叠面板：高低水位回差设置、紧急停录红线、手动「立即执行清理」按钮；
  - 友好的表单校验（数字区间、低水位严格小于高水位校验、必填项校验）。

## Acceptance Criteria

- [ ] **路径预检与防穿透**：通过 `POST /api/v1/system/storage/test` 能够准确识别只读、无权限、不存在的非法路径，以及返回正确的挂载点与文件系统信息。
- [ ] **存储遥测指标准确性**：`GET /api/v1/system/storage/status` 能够精准返回 `statfs` 采集的磁盘总量、已用、空闲，以及 Zhulong 媒体文件占用大小与当前健康状态。
- [ ] **动态配置持久化与校验**：`PUT /api/v1/system/storage/config` 支持动态修改根路径与策略参数，校验低水位 < 高水位，配置持久化落盘且重启有效。
- [ ] **双水位滞后回差淘汰验证**：单元测试/集成测试模拟高水位触发，清理器能够按优先级淘汰文件，降至低水位以下后自动休眠，中间具备流控休眠避让。
- [ ] **热切换与历史回放平滑消亡**：修改根路径后，新写入指向新路径，旧路径上的存量文件仍能正常读取，并在清理时优先被淘汰。
- [ ] **极限低空间停录熔断**：当磁盘可用空间低于设定的紧急阈值时，`CanWrite()` 返回 false，触发熔断告警；空间恢复后自愈。
- [ ] **手动清理触发**：`POST /api/v1/system/storage/cleanup` 能够安全触发一轮清理并返回清理释放的文件数和字节数。
- [ ] **前端界面完整性**：在「系统设置 - 存储设置」中能够直观呈现容量大盘，支持路径测试、策略修改与保存，提供中英双语国际化支持。
