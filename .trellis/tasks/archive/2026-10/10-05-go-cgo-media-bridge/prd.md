## 目标
在 Go 业务层可安全使用既有 Native 探测、物理流消费和按需压缩包订阅能力；在没有板卡的开发主机上形成独立可验收的桥接交付，为摄像机业务和 WebSocket 提供 Go 原生接口。

## 需求
- R1：保持现有 New / Start / Stop / Ready / Close 兼容，包括重复调用及 Close 后再次 Start。上层不接触 C 类型或裸指针。
- R2：支持 H.264/H.265 独立探测，返回宽高、有理数帧率、源时间基、完整参数集。未知帧率与缺失参数集不伪造；超限明确失败，不能静默截断。
- R3：请求取消/超时能停止自己的探测，不停掉其他探测或正在预览的物理流；不留下后台孤儿操作。引擎关闭必须等待其所属探测和订阅完全退出。
- R4：支持按有效 RTSP URI、传输参数和消费者身份获取/释放物理流，查询 Native 状态；保持单物理连接、重复消费者拒绝、配置冲突及 8 秒宽限期语义。
- R5：只有持有效 Preview 消费引用才能订阅；无人订阅时没有包回调。Go 可异步消费压缩包，数据在 Native 回调返回后仍有效。
- R6：保留 codec、带符号 PTS/DTS、存在标志、源时间基及关键帧标志，不将原始 packet 或 extradata 宣称为统一 Annex B，也不自行转码或生成时间戳。
- R7：订阅缓存有包数和字节限制。慢消费者/超大包得到明确终态，不阻塞其他消费者，不丢弃参考包后假装连续正常播放。
- R8：退订/释放/Stop/Close 的并发与失败路径有确定所有权；完成清理后不存在在途 Native 回调，不重复释放、使用过期资源或遗留协程。
- R9：错误可通过 Go 类型/错误分类识别，文本不包含 RTSP URL、凭据、原始 FFmpeg 日志。不得把当前 Native IO 错误猜成鉴权失败。

## 验收标准
- [x] AC1：既有生命周期测试和上层宿主启动/关闭回归通过；重启后旧 Stream / Subscription 无法操作新一代资源。
- [x] AC2：真实 loopback RTSP 经静态 FFmpeg → Native → CGO → Go 路径验证 H.264/H.265、TCP/UDP、元数据及 >512 字节参数集，非仅 mock 回调。
- [x] AC3：同 URL 同配置的不同消费者只有一个物理连接；重复身份/不同配置拒绝；最后释放进入宽限期，重获取消释放；宿主测试用连接计数给证据。
- [x] AC4：无订阅零包回调；订阅失败、重复退订、退订与回调并发、Stop/Close 与订阅并发均不悬空访问；token 分配/回收计数最终平衡。
- [x] AC5：接收到的 Go 包和参数集在 Native 生命周期结束后内容仍正确；零长度/异常长度及时间戳缺失不越界。
- [x] AC6：有界队列过载产生明确错误并安全退订；正常订阅不受慢订阅拖累；Go 缓存清理有上界，不继续发送不完整参考链。
- [x] AC7：探测取消覆盖发起前、注册竞争、open/info 阻塞和引擎关闭；不会中断另一条正常流或另一项探测，返回前完成本次资源清理。系统 DNS 不可抢占边界单列，不以测试源推导任意网络硬实时保证。
- [x] AC8：Go vet、race、cgocheck2 与全栈 make check / make smoke 通过；涉及 Native 产品代码时额外运行 Native sanitizer 门禁。结果按实际执行平台报告。
- [x] AC9：日志/错误文本的凭据泄露回归通过；无新增 Web/HTTP/数据库依赖侵入 engine。

## 范围外与交接
- 摄像机 CRUD/迁移/AES-GCM、结构化及模糊裸 URL 解析、Probe 入库门禁、业务四态/重连/SSE：后续摄像机子任务。
- WebSocket 库/鉴权/协议、Hub 多连接分发与参数集初始化：后续分发子任务；不宣称此任务已能浏览器播放。
- 前端、解码、录像、VPU/NPU、RKNN/MPP/RGA 和板端部署均不在本任务；平台 SDK 与量化类型不适用。
- 不顺带升级 FFmpeg、工具链或修改 Native 公共 ABI。若现有 ABI 不足以达成这里的验收，先回到设计审阅。

## 依赖与验证边界
- 可在现有宿主 ABI 上开展，不等待上游任务完整归档；这不是 RK3568 用户态/架构已经确认。
- 当前环境观测：Darwin arm64，Go 1.27.1（与 go.mod 一致），Apple clang 17.0.0，Python 3.9.6；固定 FFmpeg 7.1.5。
- 上一轮宿主 native-test/check 通过属于基线，不替代本任务变更后的验收。
- 摄像机与 WebSocket 子任务必须在本桥接接口审阅/验收后接入；父任务仍承担跨子任务最终验收。
