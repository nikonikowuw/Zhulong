# 需求文档：前端实时预览能力与多分屏播放器集成

## 1. 目标 (Goal)

构建 Zhulong 边缘异构系统的前端实时视频监视大屏与播放控制中枢（Live View），位于 `web/src/features/live/` 并在 `/live` 提供独立一级导航：
- 集成支持 H.264/H.265 的低延迟自适应播放器（Jessibuca 模式：优先 WebCodecs GPU 硬解，次选 MSE，兜底 WASM SIMD 软解）；
- 提供 1/4/9/16 多画面网格分屏与全局大屏满高视口排布，支持窗口拖拽/快速切换摄像机；
- 实现前端本地单例流复用连接池（Stream Connection Pool）与客户端引用计数机制，避免多窗口选同一相机造成重复 WebSocket 连接；
- 完备的视频监控工业级 UX：快捷键防误触、流断开退避自愈、播放质量监视（FPS/分辨率/码率）、AI 检测框 Canvas 叠加图层预留。

---

## 2. 核心需求 (Requirements)

### 2.1 路由切片与导航架构 (Routing & Decoupling)

- **R1.1 独立一级路由**：在 `web/src/routes/_authenticated/live/index.tsx` 挂载 `/live` 路由，与设备管理（`/cameras`）彻底解耦。
- **R1.2 侧边栏与 CommandMenu 集成**：在 `sidebar-data.ts` 中注册实时预览入口（使用 `Monitor` 图标），支持全局快捷键 `Ctrl+K` 搜索定位。
- **R1.3 满高流式工作区**：适配 `has-data-[layout=fixed]:h-svh` 满高视口，无缝填满控制台工作区，无外部营销页居中容器包裹。

### 2.2 多画面网格与分屏管理 (Grid & Layout Management)

- **R2.1 多分屏模式切换**：支持 1 画面、4 画面（2x2）、9 画面（3x3）、16 画面（4x4）四种布局预设，分屏切换平滑过渡。
- **R2.2 活跃窗口与选中聚焦**：单屏高亮选中（Active Cell），支持双击单窗临时全屏/恢复原网格，支持全屏大屏展示（Browser Fullscreen）。
- **R2.3 摄像机抽屉/选择面板**：左侧或悬浮面板提供摄像机资产列表（在线/离线状态指示），支持点击或快速分配摄像机到当前选中的分屏格子。
- **R2.4 键盘快捷键守卫**：支持按键 `1` / `4` / `9` 快速切换分屏，支持 `Esc` 退出放大；当处于输入框、下拉框聚焦或弹窗开启态时静默拦截快捷键，防止误触。

### 2.3 播放器集成与自适应解码 (Player Integration)

- **R3.1 协议与编码支持**：支持通过 WebSocket 接收 H.264 / H.265 码流，实现毫秒级（<300ms）超低延迟播放。
- **R3.2 三级解码降级机制**：
  1. 第一梯队：WebCodecs GPU 硬件解码（优先，极低延迟与 CPU 占用）；
  2. 第二梯队：HTML5 MediaSource (MSE) 硬件解码；
  3. 第三梯队：WASM SIMD 软解兜底（老旧浏览器或缺少硬解驱动时保障可用）。
- **R3.3 播放生命周期与显存安全**：组件卸载或切流时显式调用播放器 `destroy()`，释放 Canvas、Worker、WASM 实例及 GPU 显存，杜绝内存泄漏。
- **R3.4 播放控制与信息浮窗**：每个分屏窗口提供悬浮工具栏：主流/子流切换、静音/音量、抓拍截图（PNG）、单窗全屏、关闭；支持悬浮展示实时分辨率、实时 FPS 与连接状态。

### 2.4 前端单例流连接池与引用计数 (Stream Multiplexing & Ref-Count)

- **R4.1 客户端单例池**：建立基于 `cameraId`（或 streamId）的单例流连接管理器 `streamConnectionPool`。
- **R4.2 引用计数维护**：
  - 首个分屏挂载摄像机 A（$0 \rightarrow 1$）：真正向后端发起一条 WebSocket 流连接并初始化解码流源；
  - 多个分屏同时选择摄像机 A（$1 \rightarrow N$）：直接复用已有流对象，共享帧数据渲染至各个分屏窗口，禁止在同一浏览器标签页创建多条重复 WebSocket 连接；
  - 分屏窗口关闭或切换摄像机（$N \rightarrow 0$）：引用计数归零，延迟（或即时）关闭底层 WebSocket 并释放对应流资源。
- **R4.3 零转码直连与协议扩展预留**：兼容后端未来标准 WebSocket-FLV / Raw Annex-B WebSocket 流协议，并内置 Mock/测试图卡模式用于离线独立验证。

### 2.5 异步状态与容灾自愈 (Resilience & States)

- **R5.1 完整异步三态**：
  - 空状态（Empty）：分屏未配置摄像机，展示快捷分配摄像机引导；
  - 加载态（Loading）：连接中、握手与关键帧等待中的骨架动画/Spinner；
  - 异常态（Error）：流断开、鉴权失败或网络超时提示，并展示手动重试按钮。
- **R5.2 断流自动重连与防抖**：遇到意外掉线时，执行指数退避重连（1s, 2s, 4s, 8s），恢复后自动重现画面。

## 3. 验收标准 (Acceptance Criteria)

- [x] **AC-1 路由与导航**：访问 `/live` 能正确加载多画面监控大屏，侧边栏存在高亮的“实时预览”菜单项，支持 CommandMenu（`Ctrl+K`）快速跳转。
- [x] **AC-2 网格与分屏控制**：1/4/9/16 宫格切换功能正常；双击可将当前窗口单独放大，再次双击或按 Esc 恢复网格；全局快捷键 `1`/`4`/`9` 生效且在 Input 聚焦时被正确屏蔽。
- [x] **AC-3 多窗口单例流复用**：在 4 分屏中，将 2 个或更多格子同时配置为同一台摄像机，开发者工具 Network 面板中仅存在 1 条针对该相机的 WebSocket 连接；两窗画面保持同步播放；关闭所有格子后 WebSocket 正确断开。
- [x] **AC-4 播放器三级自适应与控制**：集成封装 Jessibuca 播放器组件；支持画面抓拍下载；支持静音/开启声音；能够展示码流状态（FPS、分辨率、播放器工作模式：WebCodecs/MSE/WASM）。
- [x] **AC-5 异常容灾与显存安全**：当 WebSocket 异常中断时展示断线提示并执行退避重连；组件销毁或页面切换后所有播放器实例与 Worker 被干净释放，无控制台报错或内存泄漏。
- [x] **AC-6 代码规范与质量门禁**：遵循 `shadcn-admin` 前端规范（零 any、Tailwind v4 OKLCH 语义色、无未使用代码），`pnpm build` 与 `pnpm lint` 编译通过。
