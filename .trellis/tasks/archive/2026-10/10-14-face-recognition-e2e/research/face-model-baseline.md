本文件是 `10-14-face-recognition-e2e` 全部子任务的共享证据来源，取代任何
「模型应该怎么用」的推测表述。

> ⚠️ 本文所有数值都是 **float ONNX 基准**，不是板端结果。板端对比方法见 §7。

## 2. 预处理契约（由官方公布数值反证，非推测）

`facelivtv2-l` 的 README §8 公布了 float ONNX 的精确数值。用它们反证预处理：

| 项 | 结论 | 证据 |
| --- | --- | --- |
| **通道序** | **RGB** | RGB 复现 README 全部数值；BGR 全部不匹配 |
| 特征归一化 | `(x − 127.5) / 127.5` | 复现 norm 10.0972 / 10.6698 / 12.7857 |
| 检测归一化 | `(x − 127.5) / 128.0` | 标准 SCRFD |
| 布局 | NCHW | 输入形状 `[1,3,H,W]` |
| 插值 | `INTER_LINEAR` | 与 README 数值吻合 |

### 2.1 反证结果（`scripts/embed_check.py`）

```
channel order = RGB
  face_a1: norm=10.0972 (expect 10.0972)  head=[-0.2670, 0.3539, 0.8917, 0.6197, -0.1279]  ✅
  face_a2: norm=10.6698 (expect 10.6698)  head=[-0.5242, -0.0067, 0.9970, 0.6192, -0.0307]  ✅
  face_b1: norm=12.7857 (expect 12.7857)  head=[ 0.7236,  0.2250, -0.3486, -0.0361, -0.2126]  ✅
  cosine(a1,a2) = +0.9235  (documented +0.9235)  ✅
  cosine(a1,b1) = -0.0763  (documented -0.0763)  ✅

channel order = BGR
  全部不匹配  ❌
```

⚠️ **为什么这条证据重要**：通道序写错时模型**不报错、不崩溃**，只是产出错误特征，
表现为「匹配率莫名很低」。逐位判据把它变成可检测的错误。

### 2.2 ⚠️ 检测 score 输出**已含 Sigmoid**

```
ONNX 图内算子: Sigmoid 节点数 = 3
Sigmoid 节点输出: {'443', '493', '468'}   ← 正是 3 个 score 输出
graph outputs 前 3 项 直连 Sigmoid: True / True / True
```

**消费方不要再做 sigmoid。** 原始 score 值域实测 `[0.0003, 0.1066]`（未归一化前的
logit 会落在更大范围）。初版探测脚本因误加 sigmoid 得出「检不出脸」的错误结论。

## 3. 对齐模板

两个模型的 README **逐位相同**的 ArcFace 5 点模板（112×112 坐标系）：

```python
[[38.2946, 51.6963],   # 左眼
 [73.5318, 51.5014],   # 右眼
 [56.0252, 71.7366],   # 鼻尖
 [41.5493, 92.3655],   # 左嘴角
 [70.7299, 92.2041]]   # 右嘴角
```

- 检测器的 `kps` 输出维度 **10 = 5 点 × (x, y)**，正好喂给对齐。
- 关键点顺序按惯例为 `[左眼, 右眼, 鼻, 左嘴, 右嘴]`。
- 对齐变换用**相似变换**（旋转 + 均匀缩放 + 平移，4 DoF）。

⚠️ **不要用完整 8 DoF 单应**：会产生剪切形变，使 embedding 偏移。
⚠️ `cv2.estimateAffinePartial2D` 的 `method=0`（最小二乘）会抛
`Unknown or unsupported robust estimation method`；5 点场景下
`LMEDS` 也无意义（没有可剔除的离群点）。`scripts/sweep.py` 里用
**手写 Umeyama 相似变换**（SVD 求解），已验证可用。

## 4. ⚠️ 分布外输入：裁剪好的人脸照**不能直接送检测器**

`aligned_112x112` 的证件照是**人脸占满全帧**的裁剪图，送入检测器：

| 输入 | 检测 score |
| --- | --- |
| 原证件照 112×112 直接放大 | **0.1066**（检不出） |
| 加 50% 边距 | **0.8457** |
| 加 100% 边距 | 0.7235 |
| 加 200% 边距 | 0.8427 |

**这是检测器的分布外输入**，不是 bug：SCRFD 在含背景的场景图上训练。

**对实现的直接影响**：人员底库登记照是裁剪好的人脸特写，
**登记路径不应假定「送检测器就能得到框」**。需要显式的降级策略：
先尝试检测，失败则按「已裁剪」处理（直接 resize 到 112×112，跳过对齐）。

## 5. ⚠️ 平台性能约束：RK3568 上 facelivtv2-l 有 48 个 CPU 算子

上游 README §9 的实测数据（**非本仓库实测，引自已归档的板端证据**）：

```
RK3568 FP16 图算子分布（共 242 个）:
  NPU: 192    CPU: 50   ← 其中 48 个是 MHLA 块的 layout 转换

实测延迟（NPU 900MHz, librknnrt 2.3.2, 单流）:
  fp16:  19.9 ms (50.2 fps)   cosine 0.99997 to float
  int8:  11.75 ms (85.0 fps)  ⚠️ cosine 仅 ~0.86
```

上游尝试过四种改写（Conv2d 重写、zero padding、静态 split、强制 `op_target`）
**全部无法把这 48 个算子移到 NPU**。

| 平台 | CPU 算子数（不含 I/O） |
| --- | --- |
| RK3566 / **RK3568** | **48**（24 Reshape + 24 Transpose） |
| RK3562 / RK3576 / RK3588 / RV1126B | **0** |

⚠️ **int8 的 cosine 0.86 是识别级别的灾难**：特征空间已显著偏移，
同一个人可能都对不上。**在 RK3568 上必须用 fp16。**

## 6. 精度实测（SCface，130 人真实监控画面）

### 6.1 精度由人脸像素尺寸主导

| 距离档 | 画面尺寸 | 人脸宽度 | rank-1 | 同人均值 | 异人均值 |
| --- | --- | --- | --- | --- | --- |
| 1 | 75×100 | ~22 px | **54.7%** | +0.1586 | +0.0091 |
| 2 | 108×144 | ~36 px | **89.5%** | +0.3072 | +0.0101 |
| 3 | 168×224 | ~64 px | **98.7%** | +0.4358 | +0.0104 |

**结论：精度是数据分辨率的函数，不是管道缺陷。** 人脸 < 25px 时识别不可靠。

⚠️ 初测在距离 1 上得到**负分离间隙**（`same.min < diff.max`），一度被误判为
管道 bug。跨三档扫描后才确认是分辨率限制。**不要在单一距离档上下结论。**

### 6.2 阈值工作点标定（距离 3，903 正 / 116487 负样本对）

| threshold | FAR% | FRR% |
| --- | --- | --- |
| 0.05 | 19.511 | 0.22 |
| 0.10 | 3.410 | 0.55 |
| **0.15** | **0.403** | **2.44** |
| 0.20 | 0.049 | 5.87 |
| 0.25 | 0.003 | 11.41 |
| 0.30 | 0.001 | 18.27 |
| 0.40 | 0.000 | 36.21 |
| **0.50** | **0.000** | **64.23** ⚠️ |
| 0.60 | 0.000 | 89.81 |

**EER ≈ 1.42% @ cosine ≈ 0.15**；rank-1 = 891/903 = **98.7%**。

⚠️⚠️ **模型 README 的 `0.50` 默认阈值实测 FRR = 64.23%** —— 直接采用会漏掉
三分之二的人。README 自身也声明「`0.5` 是 demo 默认值，**不是标定工作点**」。

**部署阈值必须按自身数据重新标定**，并随算法包 manifest / config schema 暴露为可配置项。

### 6.3 对齐往返自检（隔离对齐误差）

`aligned_112x112` 已是 ArcFace 对齐结果，因此
`直接取特征` vs `检测→对齐→取特征` 的 cosine 反映**纯对齐误差**：

```
n=30   mean = +0.9291   min = +0.7898   p10 = +0.8586
检测 landmark 相对模板平均像素误差 = 2.61 px（p90 = 5.53 px）
```

逐点误差分布：`[1.17, 2.20, 3.13, 3.38, 3.18]` px —— 嘴部/鼻部误差大于眼部。
模板的瞳距约 35 px，故 ~2 px ≈ 6%。

## 7. 黄金参照与板端对比方法

`scripts/finalize.py` 产出 `golden_reference.npz`（**未提交**，可复现）：

```
ids        (130,)       identity 字符串
embeddings (130, 512)   float32 基准特征
template   (5, 2)       ArcFace 模板
```

复现：

```bash
RKNN_MODEL_ZOO=~/dev/rknn_model_zoo \
  ~/dev/rknn_model_zoo/.venv/bin/python \
  .trellis/tasks/10-14-face-recognition-e2e/research/scripts/finalize.py
```

**板端 / C++ 验收判据**（对每个 identity 计算 cosine vs 基准）：

| 后端 | 期望 cosine vs float |
| --- | --- |
| float ONNX（本基准） | 1.0000 |
| RKNN **fp16** | > 0.999（上游实测 0.99997） |
| RKNN **int8** | ⚠️ ~0.86（上游实测，**不可接受**） |

**cosine 明显低于上述值 = 预处理或量化漂移**，必须先解决再谈匹配率。
