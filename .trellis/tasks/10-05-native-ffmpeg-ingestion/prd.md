# Native C++ 引擎与静态 FFmpeg 接入

## 目标
交付媒体接入父任务阶段一（Step 1.1～1.4），为后续 Go 摄像机业务与预览提供可测试的原生拉流底座。

## 来源与范围
父任务：`.trellis/tasks/10-05-media-ingestion/`，保持父任务其余需求不变。
- 裁剪 FFmpeg 静态接入、自包含部署，不依赖目标设备包管理器。
- 扩展纯 C ABI：探测、物理流获取/释放、包订阅与注销。
- 单物理流复用、消费者引用计数、8 秒 grace period 及取消释放。
- RTSP TCP 优先、UDP 可配置，H.264/H.265 元数据与参数集提取。
- 独立探测超时、默认 5 秒无数据超时、主动停止中断与线程汇合。
- Native 测试和现有 Go 引擎静态链接回归；必要的 Go 链接声明调整属于本任务，Go 新增订阅封装不属于本任务。
- 用户明确要求交叉编译：在开发主机完成目标架构 FFmpeg、C++ Engine 与 Go/CGO 的构建及最终链接，开发板只接收产物并执行运行验证，不承担编译。
- Engine 持续修改时支持增量构建；FFmpeg 以源码版本、裁剪配置、目标平台和工具链/sysroot 身份隔离缓存，不因 Engine 修改而重新构建。宿主与目标产物必须隔离。

## 仓库证据
- `native/CMakeLists.txt` 当前只有 C++17 引擎静态 stub 与两个生命周期测试，没有 FFmpeg 依赖。
- `native/include/Zhulong/engine.h` 只有 create/start/stop/destroy；需保留现有符号和错误码。
- `internal/engine/engine.go` 同时有 Linux 与 Darwin CGO 链接声明。
- `README.md:15` 声明 macOS arm64 验证基线，Linux 使用本地工具链，不承诺交叉编译与板端兼容。
- 本次规划环境为 Linux x86_64，Go 1.27.1、CMake 3.31.6、GCC 14.2.0；pkg-config 未发现 FFmpeg 开发库。未确定可用静态依赖，不能把系统动态库当作静态验收。
- 根 Makefile 与其他业务文件有既存修改，实施必须保留，禁止整体覆盖。

## 验收标准
- [ ] 明确 FFmpeg 来源、固定版本、完整性验证、裁剪配置、静态依赖和许可证交付方式；最终链接不依赖 FFmpeg 共享库。
- [ ] Native 构建、CTest 和纯 C ABI 编译/链接测试通过，原有生命周期语义保持兼容。
- [ ] 同一规范 URL 多消费者仅创建一个物理连接；重复消费者的行为明确且不会错误增加引用；归零延迟释放可取消。
- [ ] 探测获得有效 H.264/H.265 元数据，错误/超时不会泄漏句柄、包、线程或输出凭据。
- [ ] 实际阻塞网络路径能被超时与停止打断；停止及退订完成后无在途回调。
- [ ] 无预览订阅时没有包回调；包由 Native 分配并释放，仅在回调期间借用。
- [ ] Linux 本机验证与其他平台未验证项分开报告，不把模拟源测试当作真实摄像机/板端验收。
- [ ] 在开发主机交叉编译完整 Go/CGO/Native/FFmpeg 链路；检查目标 ELF 架构、解释器与运行库符号需求，并单列板端运行验证结果。
- [ ] 修改 Engine 后只增量构建受影响对象并重新链接宿主程序，不重建未变更的 FFmpeg；交叉编译测试程序不直接在宿主机执行。

## 工具链兼容约束
- 用户明确指出实际开发环境大概率没有 GCC 14；本机 GCC 14.2.0 仅是环境观测，不是最低版本要求或发布基线。
- 已确认：保持 C++17，不预先硬定 GCC 最低版本，也不采用 GCC 9 作为已承诺基线。不得依赖 GCC 14 专属能力；通过实际语言/标准库功能检查以及 Native、FFmpeg、最终 CGO 链接构建验证所用工具链，并记录已验证版本。
- 源码工具链支持与部署系统运行兼容性分开验收；本机编译通过不代表旧系统或其他架构运行通过。
- 保留现有 C++17 要求，若实际工具链无法满足则先评估，不擅自升级用户工具链或提高版本门槛。
- FFmpeg 静态链接不等于消除 glibc/libstdc++ 版本依赖；发布兼容性需单独检查。

## 目标设备与延后验证
- 首个目标 SoC 已由用户确认为 Rockchip RK3568；用户记忆中镜像为 Debian。用户明确板子暂不在手边，具体版本、用户态位数、内核与运行库尚未实测，仓库未发现板卡上下文或 sysroot 配置。
- 通用 Native 与交叉构建机制可继续规划；实际板端发布 profile 和兼容验收须在拿到镜像/SDK/sysroot 或板端证据后完成。不能仅凭 RK3568 的 64 位 CPU 推定安装了 arm64 用户态，不把示例交叉构建成功标记为 RK3568 板端验收通过。
- 板端仅需只读环境采集与运行测试，不需要编译器。不因暂缺板卡而取消交叉编译交付要求。
- 本阶段仅涉及通用 RTSP/FFmpeg 拉流，不引入 MPP/RGA/RKNN SDK；SDK 版本未知，NPU 量化类型不适用。

## 设计待修正项
- 父设计解码前丢 B/P 包与 PRD 连续 GOP 要求冲突；本任务不实现该丢包方案，也不冒充实现硬件解码。
- 父设计固定 512 字节 extradata 不能静默截断，应在子设计中明确容量不足或动态释放契约。
- 注销必须等待在途回调结束；仅从列表移除不足以允许未来 Go 侧删除 cgo.Handle。
- FFmpeg 静态库需传递到最终 Go 链接，不能把链接到一个 CMake STATIC target 误认为已合并所有依赖归档。
