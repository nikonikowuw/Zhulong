# 人员批量导入

## Goal

让管理员通过 CSV 一次建立多条人员档案，并在导入前识别问题、导入后追踪成功与失败，减少逐条建档工作且避免覆盖既有人员数据。

## Background and Confirmed Facts

- 现有人员领域位于 `internal/person`，人员档案包含姓名和可选外部工号 `personId`。
- `persons.person_id` 可为空且非空唯一；已绑定工号不可修改。
- 人脸照片通过独立的人脸录入接口处理，不属于人员创建载荷。
- 普通 API 请求体限制为 1 MiB；文件上传路由有独立大小上限。
- 前端人员切片位于 `web/src/features/persons`，使用 TanStack Query、Zod、三语 i18n 和 shadcn/ui。
- 当前没有人员批量导入接口、导入历史表或 Excel 解析依赖；Go 标准库支持 CSV。

## Requirements

### R1. 文件格式与范围

- R1.1 支持 UTF-8 CSV，兼容 Excel 导出文件的 UTF-8 BOM。
- R1.2 首期固定使用 `name` 和 `personId` 两列；`name` 必填，`personId` 可选。列顺序可变，列名须精确匹配；文件表头错误或无法解析时返回文件级错误，不写入任何人员。
- R1.3 本期只导入人员档案，不导入人脸照片，不支持更新、删除或覆盖既有人员。

### R2. 预校验与预览

- R2.1 上传 CSV 后先进行完整解析和业务校验，不产生人员写入。
- R2.2 预览提供可导入/失败数量及逐行结果；失败结果包含原始行号、字段和稳定错误码，前端按当前语言显示错误原因。
- R2.3 校验姓名非空且不超过现有 64 字符规则；工号遵循现有 trim、64 字符上限和条件唯一规则。
- R2.4 同一文件内重复的非空工号以及与库中已存在工号冲突的行标为失败，不覆盖已有人员；空工号允许多行。
- R2.5 文件大小、记录数须受限；本期使用固定的有界常量，文件级超限直接返回错误并不写入任何人员。

### R3. 确认导入与结果

- R3.1 用户确认后，使用同一 CSV 重新解析并校验，仅创建确认时仍有效的行；失败行跳过，响应逐行给出成功/失败结果及总计。
- R3.2 如果确认时数据库中出现新的工号冲突，该行失败并反馈，不覆盖既有人员；其他有效行仍可成功。
- R3.3 系统性数据库/服务故障时，整次确认操作回滚，不向客户端报告部分成功。
- R3.4 预览不产生持久化的导入任务记录；确认时再次上传同一份 CSV，服务端重新解析和校验原文件，不信任客户端传回的行状态或人员数据。

### R4. 前端交互

- R4.1 人员管理页面提供批量导入入口，上传 CSV 后展示预览、错误行和确认导入操作。
- R4.2 导入完成后显示成功/失败统计、逐行原因，并提供下载失败行 CSV 供修正重传。
- R4.3 所有可见文案提供简体中文、繁体中文、英文三语；异步过程具备 loading/error/success 状态。

### R5. API 与审计

- R5.1 新增预览与确认 API，遵循统一响应信封、请求/响应类型命名和 Swagger 文档规范。
- R5.2 上传端点注册在独立 `upload_routes`，保留认证、审计和请求体限制。
- R5.3 导入确认操作产生一条审计事件，不记录上传内容或敏感的整行数据。

## Acceptance Criteria

- AC1：含 UTF-8 BOM 的合法 CSV 可成功解析；表头列顺序变化不影响解析。
- AC2：缺列/重复列/无效 CSV/空文件/超限文件得到明确文件级错误，且不创建人员。
- AC3：预览报告准确区分可导入行和失败行，并指出原始行号、字段和失败原因；预览后数据库人员数量不变。
- AC4：空姓名、超长姓名、超长工号、库内重复工号和文件内重复工号按行标错；多个空工号可通过校验。
- AC5：用户确认后有效行创建成功，失败行不创建，重复工号不覆盖任何既有档案；确认响应包含准确汇总和逐行结果。
- AC6：确认阶段遇到某行新出现的唯一键冲突时，仅该行失败，其余有效行仍成功；系统性存储故障时整次确认回滚。
- AC7：前端完整支持上传、预览、逐行错误、确认、结果、失败 CSV 下载和列表刷新，并覆盖简中/繁中/英文。
- AC8：新增 API 有 handler/service/store 与浏览器前端测试覆盖；API 文档更新，`make check` 通过。

## Out of Scope

- 原生 `.xlsx` 工作簿解析。
- 人脸照片、压缩包及脸部特征提取。
- 更新或删除已有人员、工号映射/覆盖策略。
- 后台异步任务、导入历史、断点续传和定时同步。
- 可配置字段映射、预览期间持久化暂存和导入撤销。

## Key Decisions

- 用户确认使用 CSV 导入人员档案，不包含人脸照片。
- 用户确认按有效行导入、失败行指出错误，而不是一个业务错误拒绝整批。
- 采用成熟的两阶段交互：服务端预校验预览，用户确认后导入有效行。
- 不更新或覆盖已存在人员；工号唯一冲突按行报告。
- 业务行错误允许部分成功；系统级存储故障仍整体回滚。

## Risks and Deferred Items

- CSV 硬上限在本期固定为 2 MiB 与 1000 条数据行，低于现有上传组的宽松请求体限制。
- 预览与确认之间存在数据变化窗口；确认接口必须重新校验唯一性，依赖数据库唯一约束处理并发冲突。
- 失败 CSV 中应安全编码 CSV 字段，避免公式注入；原始姓名/工号不得直接拼接到可执行公式。
