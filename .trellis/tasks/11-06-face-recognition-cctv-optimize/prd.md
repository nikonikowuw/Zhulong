# 优化 CCTV 人脸识别算法包

## Goal

改进 CCTV 人脸识别的质量评估、人员级候选及拥挤场景召回，不以降低匹配阈值换取更多命中。
用户已批准任务创建、第一阶段包内范围及修订后的最终规划方案，进入实施阶段。

## Confirmed Facts

- 现有几何评分未消除滚转，使用随全图高度变化的归一化长度判据，偏航比对越过单眼的侧脸/坏点会因 `std::abs` 反向反弹，也没有图像清晰度或曝光检查。
- 流式识别已有检测 → 几何门禁 → 112×112 RGB 对齐 → 特征 → 比对链路。
- Matcher 按照片模板排序，同人多模板会重复占用 Top-K。
- SCRFD 在 NMS 前仅保留 128 个候选，重复 anchor 可能挤掉其他人脸，且小顶堆在等分时弹出顺序未定。
- 两档位是自包含副本，通用算法修复必须同步并通过漂移门禁；`check_package_drift.py` 只比较 `src/` 与 `tests/`，`config.schema.json` 需额外比对。
- 产品源码树（`packages/**`、`native/**`、`internal/**`、`web/**`）干净，仅存本地环境文件与本任务目录。
- 基线为绿：`make pkg-drift-check` 通过，包内 `make unit-test` 通过。
  本机已有 SDK 与 ONNX Runtime 前缀；逐档位可用性仍在实施验证时确认。

## Requirements

- 在像素空间建立眼线局部有向坐标系，消除全图分辨率、长宽比和滚转对姿态分量的非预期影响。
  旋转必须在像素空间做：归一化坐标的 x/y 尺度不同，直接旋转等于把画面按长宽比拉斜；偏航对称性在眼线有向投影上计算，鼻尖/嘴角越过端点的投影按 0 分软衰减，不得因绝对值反向反弹。
- 非有限输入（框、置信度、关键点、质量门限）、退化眼线、眼鼻嘴拓扑不成立（眼嘴倒置、左右嘴角相对眼线交叉、鼻尖落在眼线上方或远低于嘴线）必须硬拒绝；普通侧脸仍用连续软评分处理，不新增未经标定的姿态角硬阈值。
  退化判据按**滚转稳定的检测框尺度**（`min(box_w, box_h)`）归一，不用绝对像素、随图高变化的比例或与滚转耦合的单轴 `box_w`/`box_h`，名义边界对应 `|yaw| ≳ 75°`。
- 对已对齐的 RGB 脸块统计清晰度及欠曝/过曝比例，在特征提取前执行可选门禁；不引入新模型或第三方依赖。
  清晰度只对上采样（`|det(affine)| > 1`，源脸小于 112px）做仿射行列式补偿 `var_patch × max(1, |det|)`：既消除 112×112 双线性上采样让远距小脸方差系统性偏低的问题，也不对 `>= 112px` 近景清晰大脸做 `< 1` 反向折减。
- 图像门禁用**单一布尔开关**控制启停，三个阈值只承担有界标定值语义（`min_face_sharpness` 同步声明合理上限以避免 `double → float` 窄化溢出）；不要用 `0`/`1` 之类"哨兵默认值"兼作关闭（对 max 类阈值 `0` 是最严，按直觉填 0 会拒掉所有人脸）。
- 按 `person_id` 聚合 Top-K，每人以最高分照片为代表并保留其 `face_id`；同人等分按较小 `face_id` 取代表照，跨人候选等分按较小 `person_id`（再按 `face_id`、底库下标）决胜，与宿主 `person.SearchByImage` 一致。跳过空 `person_id` 的畸形模板；聚合过程避免逐人动态节点分配。
- 增加可配置的不同身份第一、第二名分差（`>=` 语义）；第二身份计算不能被输出 `top_k` 截断。
- 非有限值的过滤成本必须可控：逐元素扫底库会让内积开销翻倍，改为每个模板判一次 `isfinite(dot)`（同时拦截 `NaN` 与 `±Inf`），探针与输入门限在进循环前做一次有限性校验。
- 候选是否按匹配阈值过滤要明确：C++ 抓拍候选保持"不过滤"（未命中时也给出最像谁），与宿主以图搜人的"按阈值过滤"有意不同，并写进包说明。
- 分离 NMS 前候选预算与 NMS 后目标上限，全网格扫描、资源有界、排序确定：扫描序号同时参与 pre-NMS 小顶堆淘汰与最终排序，并在达到 post-NMS 目标上限时提前结束抑制循环。
- NMS 前预算按档位给出，不用宿主机（onnx/x86）耗时替板端定值；post-NMS 上限即每帧特征抽取次数上界。
- 图像门禁判定与比对后 `filter_unmatched` 准入判定抽为纯头文件函数，由 `build_face_item` 与包内 `unit-test` 共用，确保无模型测试直接覆盖真实产品分支。
- 新参数覆盖进程默认和任务覆盖路径，两档位 schema 与解析默认值同步。
- 保持默认匹配阈值 0.40、检测阈值 0.50、最小脸尺寸 32、综合质量阈值 0.40。
- 拟定图像门禁及身份分差默认关闭，现场标定后可逐任务启用。
- 增补包内回归和参数说明，通用逻辑同步 onnx / rk3568；本机只运行 ONNX，不执行交叉产物。

## Acceptance Criteria

- [x] 同一像素几何在不同全图尺寸、长宽比与滚转（含 90°/180° 及边界附近样本）下，姿态分量与退化硬拒结论在浮点容差内一致；左右镜像（交换 eye/mouth 索引）后 yaw/pitch 亦一致。
- [x] 非法拓扑（眼嘴倒置、嘴角交叉、鼻尖越出眼嘴合理区间、鼻尖飞出框外远端）、重合眼点、NaN/Inf（含框、分数、关键点、质量门限）无法靠高检测分或 `min_face_quality=0` 通过门禁；正常正脸与尺寸边界回归通过；~55° 普通侧脸在质量阈值关闭时不被硬拒。
- [x] 回归既有误拒：同一 32px 脸在 4K 全幅与 640×360 AI 视图裁剪下不再因图高归一化台阶而判退化。
- [x] 在源图像素空间施加固定模糊核（模拟相机 PSF）的合成清晰/模糊人脸，经对齐后在 32/64/200 三种源尺度下清晰度排序一致且近景 200px 清晰脸不被下采样折减误杀；暗/亮/均匀脸块的曝光统计符合定义，阈值边界（`Y==32`/`Y==224`）归属固定，极小尺寸/空缓冲/非法行列式安全拒绝。
- [x] 图像门禁产品函数在开关关闭时保持原决策，开启时正确执行配置边界；超上限 `min_face_sharpness` 等无效配置安全回落默认，无 `float` 窄化溢出。
- [x] 同人多模板只占一个候选名额，代表照片与身份、姓名、相似度对应正确；同人等分按较小 `face_id`、跨人等分按较小 `person_id` 定序，空 `person_id` 模板被跳过。
- [x] 分差关闭保持最高分阈值决策；开启时近分不同身份拒识、达到分差边界（`>=`）放行；覆盖单身份、同分与 `top_k=0/1`（`top_k=0` 在 schema 里不可达，只作接口级容错，不得为它放开 schema 下限）。
- [x] 非有限探针、模板或门限参数不污染结果与排序（比较器不被 NaN 破坏），维度错误条目保持跳过语义。
- [x] 合成的重复 anchor 不再因原 128 候选预算挤掉其他可检人脸，输出数量及内存仍有硬上界；含超 pre-NMS 预算的等分候选在多次运行间结果逐字节一致，且保留较早扫描序号。
- [x] `filter_unmatched` 与分差同时开启时的"疑似本人被整体丢弃"行为通过共用产品头文件函数钉住，并在包说明中写明。
- [x] 包内 `unit-test`、真实模型 sample smoke、两档位 `config.schema.json` 一致性比对、`make pkg-drift-check` 通过；C++ 改后执行 `make native-build`，收工执行 `make check`（记录既有前端格式/无关用例阻塞）。
- [x] 如验证受环境或既有问题阻塞，如实记录，不修改无关业务；不承诺未经测量的 CCTV 识别率提升。

## Out Of Scope

- 多帧跟踪/融合、跨帧状态、模型替换/量化、ROI/分块检测、默认输入分辨率变更。
- SDK / 解码 / IPC 的 YUV 色彩契约修复，以及 Go、前端、数据库、ABI 修改。
- 底库登记拒绝规则变更（`FaceExtractorContext` 仍保持单人特写与原置信度规则；仅底层 `detector.cpp` 解码预算随检测器统一演进）；新增图像门禁只接入流式识别。
- 把图像质量直接乘入原几何分，或默认启用未经 CCTV 标定的新增拒识门槛。
- 无关修复、提交、发版、硬件及干净容器测试。

## Risks

- 几何异常硬拒绝及人员级候选是有意行为变化；拓扑边界需留出俯视 CCTV 大俯仰余量，不能把普通侧脸或大俯仰正脸定义为非法。
- 清晰度受原脸尺寸、插值、噪声和曝光影响：`max(1, |det|)` 只消除 `< 112px` 小脸上采样的系统性偏低，残余误差仍需现场标定，且默认阈值只是占位值。
- NMS 预算增加会提高极端输入的后处理成本（O(n²)），需保留硬上界、给出估算并注明"未经板端实测"；x86 档位耗时不能替板端定预算。
- 提高拥挤场景召回会同时提高 post-NMS 之后最贵的每脸特征抽取次数；预算调整必须保证该上界（128）不变。
- YUV 色彩问题仍未解决，sample smoke 不能替代真实 CCTV 端到端评测。

## Open Questions

无阻塞范围问题。评审发现的清晰度下采样折减、滚转框尺度耦合、有向偏航比、小顶堆等分淘汰、产品头文件可测性及 schema 窄化边界均已在 `design.md` 收口；剩余待确认项只有占位默认阈值的现场标定。
